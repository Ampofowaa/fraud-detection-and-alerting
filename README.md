# Fraud Detection: From Anomaly Detection to Cost-Optimal Alerting

**Business question:** a fraud operations team can only review a limited number of transactions each day. *Which transactions should it review to minimise fraud losses plus review costs, and how will it know when the model needs retraining?*

**Live dashboard:** *(link added after deployment)*

## Headline results

On an **unseen test month** of real e-commerce transactions (IEEE-CIS, 89,326 transactions, 3,114 frauds worth $477k), at an assumed $5 cost per alert review:

| Measure | Result |
|---|---|
| Fraud value caught | **$370k (77.5%)** |
| Net saving vs no model (after review costs) | **$296k (62% of fraud losses)** |
| Analyst workload | ~478 alerts/day (166 per 1,000 transactions) |
| Model quality (Average Precision) | **0.545** (95% CI 0.526–0.561), 15.6x the 3.5% base rate |

The best alert volume depends on review cost: from 26 to 283 alerts per 1,000 transactions as the cost per review falls from $50 to $1.

## The project in two parts

### Part 1: Synthetic investigation ([`01_synthetic_investigation.ipynb`](01_synthetic_investigation.ipynb))
Diagnosing a broken anomaly-detection pipeline on synthetic data (labels generated by `generate_data.py`):
- Found that `contamination = 0.5` forced IsolationForest to flag half of all transactions.
- Showed that the first dataset had **no learnable signal**: even a supervised model scored ROC-AUC ≈ 0.49.
- Found that IsolationForest flags *rare* transactions rather than *risky* ones (desktop transactions 15x over-represented among flags).
- Concluded that **when labels exist, a supervised model should lead.**

### Part 2: Real transactions at scale ([`02_ieee_cis_fraud.ipynb`](02_ieee_cis_fraud.ipynb))
Testing Part 1's conclusions on 590,540 real transactions × 434 features:
- **Memory-efficient processing:** 2.08 GB → 0.97 GB with compact dtypes. Reload in 2.5 s from Parquet vs 31 s from CSV.
- **Time-based split** (train ~4 months → validate 1 month → test 1 month), so the model is always scored on future transactions.
- **Leakage-safe features:** per-card 30-day history using strictly earlier transactions only.
- **LightGBM vs baselines:** test AP 0.545, against 0.162 for logistic regression and 0.111 for IsolationForest.
- **Cost-based alert threshold** chosen on validation and applied unchanged to test.
- **Drift monitoring (PSI):** caught a non-stationary feature in an early version, which was replaced. The project also shows why label-free monitoring matters when fraud labels arrive weeks late through chargebacks.

**Honest negative results:** the IsolationForest score did not improve LightGBM as an extra feature, and score PSI stayed stable even while AP fell from validation to test. Both are discussed in the notebook.

## Dashboard
`dashboard/app.py` is a Streamlit app for a fraud team. It has sliders for review cost and alert volume, cost and capture curves, model comparison, and drift monitoring. It reads only **aggregated** results (`dashboard/data/results.json`), so no row-level competition data is published.

```bash
pip install -r dashboard/requirements.txt
streamlit run dashboard/app.py
```

## Reproducing
1. Join the [IEEE-CIS Fraud Detection](https://www.kaggle.com/competitions/ieee-fraud-detection) competition on Kaggle and download `train_transaction.csv` and `train_identity.csv` into `data/`.
2. `pip install -r requirements.txt`
3. Run `02_ieee_cis_fraud.ipynb` (about 25 minutes on a laptop). It regenerates `dashboard/data/results.json`.

Part 1's data is generated with `python generate_data.py`.

## Notes
- **Not comparable with the Kaggle leaderboard:** the competition used a different test set and ranked on ROC-AUC. This project uses its own time-based split, with Average Precision and business cost as the measures.
- **Credit:** the idea of grouping transactions by a reconstructed card identifier comes from the competition's 1st-place write-up (Chris Deotte and Konstantin Yakovlev). This project uses a simpler version.
- **Limitations:** many columns are anonymised. The data covers one e-commerce merchant over ~6 months. Labels come from chargebacks, and the review cost is an assumption.
